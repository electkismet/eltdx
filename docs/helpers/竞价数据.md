# 竞价数据

## 作用

把集合竞价过程、09:25 正式撮合和昨收放到一个结果里，并计算开盘价、开盘成交量、开盘成交额和开盘涨幅。

| 项目   | 内容                                                                                                                                    |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------- |
| 调用方法 | `client.helpers.auction_data(code, date=None)`                                                                                             |
| 返回模型 | `AuctionData`                                                                                                                         |
| 当日来源 | [`0x056a` 当日集合竞价过程快照](../methods/7709-集合竞价明细.md) + `0x0fc5` 09:25 正式撮合 + [`0x054c` 批量快照](../methods/7709-批量快照.md)中的昨收 |
| 历史来源 | 只使用 `0x0fc6`，完成一轮自动分页后，从同一份历史成交明细筛出竞价记录和 09:25 正式撮合，并读取昨收价格基数 |

## 示例

```python
from eltdx import TdxClient

with TdxClient(timeout=3) as client:
    today = client.helpers.auction_data("sz000001")
    history = client.helpers.auction_data("sz000001", "2026-05-20")

print(today.open_price, today.open_change_pct, today.open_volume, today.open_amount)

if today.series:
    for point in today.series.points[:5]:
        print(point.time_label, point.price, point.matched_volume, point.unmatched_volume)

for record in history.auction_records[:5]:
    print(record.time_label, record.price, record.auction_matched_volume)

print(history.snapshot_0925, history.pre_close_price, history.open_change_pct)
```

## 参数

| 参数                 | 含义                         |
| ------------------ | -------------------------- |
| `code`             | 股票代码                       |
| `date`             | 不传时查询当日；传入日期时固定使用 `0x0fc6` 查询该交易日 |
| `include_series`   | 是否返回竞价过程，默认 `True`；当日返回带秒时间的 `series`，历史返回只有分钟时间的 `auction_records` |
| `include_snapshot` | 是否请求 09:25 正式撮合，默认 `True` |
| `include_quote`    | 是否自动补昨收，默认 `True`；当日取自 `0x054c`，历史取自 `0x0fc6`，历史查询不会使用当前行情 |
| `pre_close_price`  | 可手动指定昨收并覆盖接口值；通常不需要传 |

## 返回字段

| 字段                | 含义                                           |
| ----------------- | -------------------------------------------- |
| `code`            | 完整代码                                         |
| `trading_date`    | 交易日                                          |
| `series`          | 当日 `0x056a` 的 `AuctionSeries` 秒级竞价过程；历史查询为 `None` |
| `auction_records` | 历史 `0x0fc6` 中 `status=8` 的竞价记录，时间只精确到分钟且同一分钟可有多条；当日查询为空 tuple |
| `snapshot_0925`   | `TradeTick | None`，09:25 正式撮合记录             |
| `pre_close_price` | 昨收                                           |
| `open_price`      | 开盘价，优先来自 09:25 正式撮合                            |
| `open_volume`     | 09:25 成交量，单位手                                |
| `open_amount`     | 09:25 成交额                                    |
| `open_change_pct` | 开盘涨幅，按 `open_price / pre_close_price - 1` 计算 |

## 两类数据怎么用

| 数据 | 看什么 |
| --- | --- |
| `series.points` | 当日 9:15 到 9:25 的秒级价格、虚拟匹配量和未匹配量变化 |
| `auction_records` | 历史成交明细中的虚拟竞价记录；时间只显示到分钟，同一分钟可有多条 |
| `snapshot_0925` | 当日或历史 9:25 的正式成交价、成交量和成交额 |

开盘涨幅和开盘金额通常看 `snapshot_0925` 更直接；当日竞价过程看 `series.points`，历史竞价过程看 `auction_records`。

不传日期时，接口使用 `0x056a + 0x0fc5 + 0x054c`。传入日期时只使用 `0x0fc6` 完成一轮自动分页，再从同一份成交明细中拆出竞价记录和正式撮合，并使用 `price_base_raw_f32` 作为昨收计算开盘涨幅。这里的“一轮”是一次 `all_history()` 调用；成交记录较多时，底层会自动请求多个 `0x0fc6` 分页。`auction_records` 只筛选主站实际返回的 `status=8` 记录；指定日期的数据中没有这类记录时返回空 tuple。
