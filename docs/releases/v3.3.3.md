# v3.3.3

发布日期：2026-11-06。

本版本修复实时行情订阅无法持续收到服务端推送的问题，并支持多连接批量订阅及自动游标续期。

## 主要变化

- `quotes.subscribe()` / `subscribe_hq()` 默认每 7 秒续期，自动携带每只股票最后收到的服务端 `update_time_raw` 游标。
- 关注代码标准化并去重，按每组最多 100 只自动拆分；每组独占原连接，1,000 只股票可通过 `pool_size=10` 订阅。
- 统一读取共享推送队列，初始行情、续期返回的增量和服务端主动推送均派发给回调。

## 修复内容

- 修正 `0x0547` 请求消息编号，恢复服务端主动推送；请求响应与主动推送分别处理。
- 保持每组订阅的连接和代码集合，续期自动更新游标，支持新交易日早盘时间变小的情况。
- 订阅结束及异常退出时释放独占连接；轮询等待时间自动避开下一次续期时刻。
- 补充游标、多组连接、错误清理和参数校验测试，以及 10 连接、1,000 只股票的实时订阅验证脚本。

## 兼容性与使用

- Python 3.10+；现有 `subscribe(codes, callback).run()` 用法自动获得续期行为。显式传 `reactivate_interval=None` 可禁用续期。
- 连接池至少需要 `ceil(去重代码数 / 100)` 个连接槽。如需同时执行其他请求，请预留额外连接槽。
- 同一客户端使用一个订阅管理全部关注代码；手动 `activate()` / `run_once()` 使用完毕后需调用 `close()`。
- 回调应及时返回。服务端覆盖与推送频率依主站和交易时段而定；断线后由调用方重建订阅。较旧的记录可能导致补发部分增量，调用方可按业务规则处理重复。
- 单个连接槽的刷新请求序号最多使用 65,535 次，耗尽时会显式报错，需创建新客户端。
