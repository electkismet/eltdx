# F10 涨跌停列表

`CWServ.cfg_fx_lbtt` 返回指定日期或日期范围内的逐股涨停、炸板和跌停列表。它和 `client.helpers.limit_ladder()` 不同：后者是基于 7709 实时行情与短线指标的组合筛选，本接口直接读取 7615 历史明细。

## 调用

```python
from eltdx import TdxClient

with TdxClient(timeout=8) as client:
    table = client.f10.limit_up_down_list("20260810")
    history = client.f10.limit_up_down_list("20260807", "20260810")
    with_summary = client.f10.limit_up_down_list(
        "20260810", include_summary=True
    )

for row in table.rows:
    print(row.full_code, row.status, row.board_level, row.name, row.reason)
print(with_summary.summary)
```

不传日期时默认查询当天；只传一个日期时按单日查询。日期支持 `YYYYMMDD`、`YYYY-MM-DD`、`YYYY/MM/DD`、`date` 和整数格式，起始日期不能晚于结束日期。

## 请求

```text
POST http://hot.icfqs.com:7615/TQLEX?Entry=CWServ.cfg_fx_lbtt&RI=
{"Params":["1","20260810","20260810"]}
```

`Params[0]` 为 `"1"` 时返回逐股明细；`include_summary=True` 会追加 `Params[0]="2"` 的市场概况表。该接口是 HTTP 7615 请求，不需要 7709 握手，也不占用行情连接池。

服务端 Entry 不接受“封单额 / 涨跌停时间 / 开板次数 / 涨跌停原因”等排序参数；截图中的“排序”是客户端页面对每个交易日、每个板位（以及炸板、跌停分组）内部做的本地排序，不会跨梯队混排。SDK 默认保留服务端原始顺序，调用方可按 `seal_amount`、`limit_time`、`broken_count` 或 `reason` 在本地排序。

## 返回模型

返回 `LimitBoardLadder`，字段如下：

| 字段 | 含义 |
| --- | --- |
| `start_date` / `end_date` | 实际查询的起止日期，统一为 `YYYYMMDD` |
| `rows` | `LimitBoardLadderRow` 逐股明细 |
| `summary` | 可选的市场概况原生行；未请求时为空元组 |
| `market_overview` / `overview` | 将市场概况映射为上涨、下跌、平盘、涨跌停家数、成交额和热门题材 |
| `ladder_counts` | 按 `lbts` 统计各板位的涨停数量 |
| `promotion_rates` | 各板位相对紧邻低一板位的晋级率；小数形式，如 `0.5` 表示 50% |
| `ladder_counts_by_date` / `promotion_rates_by_date` | 日期范围查询时按交易日分别统计，避免把不同日期合并 |
| `raw` | 详情请求的原始 JSON |
| `ok` / `error_code` | 服务端状态 |

每个 `LimitBoardLadderRow` 同时提供描述性字段和原生字段别名：

| 描述性字段 | 原生字段 | 含义 |
| --- | --- | --- |
| `trading_date` / `trading_date_value` | `rq` / `rqex` | 展示日期 / `YYYYMMDD` 日期值 |
| `board_level` / `ladder_days` | `lbts` | 涨停股票的板位 / 连板天数；其他类型的服务端值为 `0`，`board_level` 规范为 `None` |
| `highest_board_level` | `zglb` | 当天最高板；服务端在每行重复返回 |
| `code` / `market_id` | `ZQDM` / `SC` | 六位代码 / 市场号 |
| `full_code` / `market` | 派生字段 | 带市场前缀的完整代码 / 市场前缀 |
| `name` / `industry` | `ZQJC` / `sshy` | 证券简称 / 所属行业 |
| `limit_reason` / `limit_reason_extra` | `ztyy` / `ztyy2` | 第一原因 / 第二原因 |
| `seal_amount` / `limit_time` | `fde` / `ztsj` | 封单额 / 涨停时间 |
| `broken_count` / `limit_type` | `kbcs` / `ztlb` | 炸板次数 / 行类型（`1` 涨停、`3` 炸板、`0` 跌停） |
| `status` / `reason` | 派生字段 | 行类型和页面显示原因 |
| `success_rate` | `cgl` | 服务端成功率或晋级相关字段 |

`full_code` 和 `market` 会根据 `SC` 自动补出 `sz`、`sh` 或 `bj` 前缀；`raw` 保留原始字段，便于兼容服务端新增列。

## 与实时 Helper 的选择

| 需求 | 推荐入口 |
| --- | --- |
| 开盘前后快速读取当天连板结果 | `client.helpers.limit_ladder()` |
| 查询历史日期、日期范围和逐股涨停原因 | `client.f10.limit_up_down_list()` |
| 同时要页面顶部市场概况 | `client.f10.limit_up_down_list(..., include_summary=True)` |
