# v2.0.4

`v2.0.4` 相对 `v2.0.3` 完善了 `client.helpers.auction_data()` 的当日与历史竞价聚合逻辑。

## 数据来源

不传日期时查询主站当前交易日：

| 数据 | 来源 |
| --- | --- |
| 09:15 到 09:25 的竞价过程 | `0x056a` |
| 09:25 正式撮合 | `0x0fc5` |
| 昨收 | `0x054c` |

传入日期时只使用 `0x0fc6` 完成一轮自动分页，再从同一份历史成交明细中取得：

- `status=8` 的集合竞价记录；
- 09:25 正式撮合；
- `price_base_raw_f32` 昨收价格基数。

历史查询不会使用当前行情补数据。成交记录较多时，一轮 `all_history()` 会自动请求多个 `0x0fc6` 分页，避免遗漏开盘附近的记录。

## 返回结果

`AuctionData` 新增 `auction_records` 字段：

| 字段 | 内容 |
| --- | --- |
| `series` | 当日 `0x056a` 的带秒竞价过程；历史查询为 `None` |
| `auction_records` | 历史 `0x0fc6` 中的竞价记录，时间精确到分钟且同一分钟可有多条；当日查询为空 tuple |
| `snapshot_0925` | 当日或历史的 09:25 正式撮合 |
| `pre_close_price` | 当日来自 `0x054c`，历史来自 `0x0fc6` |
| `open_price` / `open_volume` / `open_amount` | 由 09:25 正式撮合计算 |
| `open_change_pct` | 根据开盘价和昨收计算 |

`0x054c` 当日行情快照只用于补昨收。接口不会再用行情快照中的开盘字段替代 09:25 正式撮合。

## 示例

```python
from eltdx import TdxClient

with TdxClient(timeout=3) as client:
    today = client.helpers.auction_data("sz000001")
    history = client.helpers.auction_data("sz000001", "2026-08-13")

print(today.series, today.snapshot_0925, today.open_change_pct)
print(history.auction_records, history.snapshot_0925, history.open_change_pct)
```
