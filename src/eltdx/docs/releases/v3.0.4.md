# v3.0.4

`v3.0.4` 修复成交明细分页合并顺序，并完善 v2.0.5 基线对照夹具的导出行为。

## 主要变化

- `client.trades.all_today()` 和 `client.trades.all_history()` 继续自动翻页，结果统一按成交时间正序返回。
- 保留每一页内部的服务端顺序，避免同一分钟内的成交被重新排序。
- 保留服务端提供的 `absolute_index`，分页合并不会重新编号。
- 成交明细原始记录、`actual_trades` 的过滤口径和其他公开模块入口保持不变。

## 修复内容

- 主站在 `start=0` 返回最新一页、后续偏移返回更早页面时，旧实现会把页面按请求顺序直接拼接，导致完整结果时间倒序；现在按页面逆序展开后恢复时间正序。
- 基线导出器遇到 v3 相比 v2.0.5 新增的模块、方法、数据类或异常时，不再因导入失败中断；缺失项会写入快照，便于继续进行公开 API 对照。
- 新增分页顺序回归测试，覆盖多页、空终止页和原始索引保持。

## 安装和平台

本版本继续支持 CPython 3.10-3.14，使用 `cp310-abi3` 产物：Windows x64、Linux x64、Linux ARM64、macOS x64 和 macOS ARM64 五个独立 ABI3 wheel，另有一个源码包。

```bash
python -m pip install --upgrade "eltdx==3.0.4"
```

## 升级注意

这是兼容性修复版本。现有 `client.codes`、`client.quotes`、`client.bars`、`client.minutes`、`client.trades`、`client.auctions`、`client.corporate`、`client.resources`、`client.f10` 和 `client.helpers` 入口保持不变。

如果业务依赖 `all_today()` 或 `all_history()` 的返回顺序，应按新的时间正序处理；如需追溯主站分页位置，继续使用每条记录的 `absolute_index`。
