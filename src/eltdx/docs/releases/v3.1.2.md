# v3.1.2

`v3.1.2` 统一集合竞价和资金流向的专用主站路由，并将两组主站测速前移到标准客户端构造阶段。

## 主要变化

- `client.auctions.series()` 的当日和历史查询统一使用 `money_flow_servers.json` 中的 35 台专用主站。
- `client.money_flow.daily()` 继续使用独立的 35 台专用主站池；普通行情、K 线和成交接口保持默认 43 台主站路由。
- 创建标准 `TdxClient` 时并发测速普通 43 台和专用 35 台候选主站，重复地址只探测一次，并分别保存客户端内存排名。
- 测速只建立临时 TCP 探测连接，不创建业务 Engine 或执行协议握手；业务连接在各连接池首次使用时按需建立，后续请求复用。
- `realtime_rank()` 文档补齐全部服务端排序字段、编号和升降序说明。

## 修复内容

- 避免集合竞价历史查询因使用普通行情主站而返回空结果。
- 避免集合竞价和资金流向在首次请求时重复测速，两个专用池共享同一份 35 台主站排名。
- MCP 客户端注册表适配客户端构造阶段测速，避免构造过程持有注册表锁阻塞其他客户端。

## 测试

- Python 公共契约、协议 golden 和 runtime loopback 回归测试通过。
- 真实主站验证覆盖 43 台普通候选和 35 台专用候选；集合竞价当日返回 82 条、历史返回 75 条。

## 升级注意

现有 API 保持兼容。标准客户端创建时会同步等待两组候选主站测速；如果需要跳过，可设置 `probe_hosts=False`。集合竞价和资金流向仍各自按首次调用建立专用业务连接。

```bash
python -m pip install --upgrade "eltdx==3.1.2"
```
