## Integration decisions and resume plan

1. Keep a unique dispatcher per exact Engine/SessionOwner, using the new PushConsumer. Cache it via owner state or equivalent owner-shared lazy storage, never one dispatcher per service getter. The runtime raw gate already forbids a competing legacy poll/drain once controlled mode starts. T18 still needs a controlled fanout/raw adapter preserving Python projection; do not simply force Python callers to fail PoolBusy after migration.
2. Dispatcher and renewal worker state must hold Weak<SessionOwner> or independent control state. Register stop/join via existing OwnerTaskGroup before a worker can run. SessionOwner strongly retaining a task whose worker permanently owns SessionOwner would create a cycle. Explicit close uses the existing single shutdown deadline; Drop sends stop only.
3. Validate positive options and supported maximum event charge, input nonempty/checked IDs and groups<=pool_size before metadata or the first pin. Load metadata before reserving every pool slot. Acquire groups of100 sequentially under one entry context and roll back ALL pins on any activation/acquisition error, including the failing group's own pin.
4. Resolve activation/push race explicitly: routes must be ready or bounded pending frames retained before the dispatcher can discard a just-activated group's first pushes. Bind to exact RawReply epoch/slot/generation, and filter requested identities before cursor mutation. No silent retargeting after source loss.
5. Implement retained typed-event memory charge including struct/vector/string backing storage and shared Bytes/raw payload retention. Runtime raw budget is a different budget. Current queue charge parameter is an internal integration seam, not a completed memory bound. Avoid counting only wire length or using fixed guessed row sizes. Check supported maximum event capacity before taking resources; account Initial/Resynchronized too.
6. Share existing quote refresh projection/decoder with M23 and depth/subscription. Expose borrowed PinnedQuoteService tied to PinnedSession. A generic TdxClient::pin has no IDs to preload; cold metadata requested while all slots are pinned must use a source-bound pinned metadata loader or a demonstrated nondeadlocking design, not an ordinary-pool metadata request that waits on its own lease. Existing HqExecutor prepare_metadata uses an unpinned shared metadata flight; do not call it blindly from pinned refresh.
7. Establishment options/token must be discarded after success. Each renewal creates a fresh finite operation with only subscription-stop/session-close cancellation; no old setup deadline. next_event cancellation/timeout ends only that wait. Own close=>None, parent/failure=>Closed/root. Parent close must release without another read.
8. Implement finite same-source resync using snapshot/refresh on subscription pins, emit Gap first, restore only on success. Reconnect/source loss must report gap/error and invalidate old immutable pin; never rebind it silently. Queue fail currently preserves an existing Gap before terminal; parent-close handling must honor the stricter immediate Closed/root contract rather than blindly reuse it.
